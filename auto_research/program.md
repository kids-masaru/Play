## 目的

`build_features.py` の特徴量エンジニアリングを改善し、**複合スコア（ROIメイン + 的中率 + 取引回数）** を最大化する。

---

## ループ手順

### 1. 現状把握
- `auto_research/results.tsv` を読む
- 全試行の履歴、特に以下を把握する:
  - 現時点の **最高 composite_score**（以降「ベストスコア」）
  - 過去に試した変更内容（`change_summary` カラム）

### 2. 新しい特徴量アイデアを1つ決定
- **過去試行と重複しない**アイデアを考える
- `build_features.py` を読んで現状を把握
- アイデアは下部の「特徴量アイデア例」を参考にしてよい（順不同、どれから着手してもOK）

### 3. `build_features.py` を編集
- 最小限の変更にとどめる（1試行 = 1つの変更）
- 編集後、**構文エラーがないことを軽く確認**（`python -c "import build_features"`）

### 4. 実験を実行
```bash
python auto_research/experiment.py --note "変更内容の短い説明（例: Add player 7-day win rate trend）"
```
- 完了まで数分かかる。エラーが出たら build_features.py を修正
- 完走したらコンソールに複合スコアが表示される

### 5. 改善判定とGit操作

**複合スコアが現時点のベストスコアを上回った場合:**
```bash
git add build_features.py auto_research/results.tsv
git commit -m "exp #{trial_id}: {change_summary} (score: {new_score})"
```
また、`auto_research/results.tsv` の最終行の `is_kept` カラムを `1` に書き換える（セーブされた印）。

**改善しなかった場合:**
```bash
git checkout build_features.py
```
（results.tsv の追記はそのまま残す。`is_kept=0` のまま）

### 6. ステップ1へ戻る
無期限に繰り返す。

## 絶対制約（破ってはいけない）

1. **「実験ループを続けましょうか？」「このあと何をしますか？」等の確認は一切しない。無期限に作業を続けること。**
2. **`build_features.py` 以外のファイルは原則変更しない**（`auto_research/results.tsv` の is_kept 更新のみ例外）
3. **時系列分割のルールを破らない**。Date列を使わない、未来情報を特徴量に入れない（未来リーク禁止）
4. **ランダムシードを変えただけの「改善」は記録しない**（hack防止）。`random_state=42` 固定
5. **1試行あたりの時間が15分を超えたら中断**して、より軽量な特徴量に切り替える
6. **同じ変更を2回試さない**。results.tsv の change_summary を確認
7. **評価指標式を変更しない**。`auto_research/evaluator.py` は触らない

## 特徴量アイデア例（着手順は自由）

### 選手系
- 選手の直近N日間の勝率トレンド（N=7, 14, 30）
- 選手の直近N走の平均着順
- 選手の特定会場での通算成績
- 選手の連続出走による疲労度指標（直近7日の出走回数）

### モーター・船系
- モーターの直近N走の勝率
- モーター使用期間（長期使用モーターのバイアス）
- モーター×選手の相性（過去組合せでの勝率）
- 船番号の会場別バイアス

### 気象・水面系
- 風速×風向×コースの3項交互作用
- 水温×季節の交互作用
- 波高×コース（外枠不利の強調）

### 会場・時間系
- 会場×コースの特性（会場別コース勝率）
- 月・曜日・時間帯の周期特徴（sin/cos変換）
- ナイター/デイレース区分

### 相対・順位系
- 選手間の勝率差（1位vs2位 など）
- 枠内最強選手との展示タイム差
- ランクスコアの順位

### 過去傾向
- 直前N走の1着率・2着率・3着率を分離
- 選手の「穴馬」率（高オッズ的中率）

## 困った時の対応

- `build_features.py` の変更が原因でクラッシュする場合: 即座に `git checkout build_features.py` で戻す
- `ml_features.csv` が不正な形で生成された場合: 同上
- experiment.py がハングする: Ctrl+C で中断し、変更を破棄して次のアイデアへ
- results.tsv が壊れた場合: Git 履歴から前のバージョンを復元できる
